# SI vs SDC — AI Profitability Comparison

## Purpose

This note captures the main economic differences between:

- **SI / Services partners**
- **SDCs — Software Development Companies**

The underlying AI workload may be similar.

What changes is the **business model around the workload**, which changes the profitability questions.

---

# Simple distinction

## SI

An SI primarily helps a customer **design, build, integrate, or transform** a solution.

Typical question:

> **Did this AI solution create enough value for the customer to justify the investment?**

The main economic lens is usually:

```text
Customer investment
        ↓
Accepted Work
        ↓
Business outcome
        ↓
Customer economic value
```

---

## SDC

An SDC primarily builds and operates **software products or capabilities used by many customers**.

Typical question:

> **Does this AI capability create enough customer value while remaining economically sustainable for the SDC?**

The economic lens is usually:

```text
Customer Value
        +
Provider Economics
```

Both matter.

---

# Side-by-side

| Dimension | SI / Services | SDC |
|---|---|---|
| Primary thing delivered | Customer solution / transformation | Software product / capability |
| Usually built for | A specific customer or engagement | Many customers / users |
| Primary profitability question | Is the customer's AI investment economically worthwhile? | Is the capability valuable to customers and sustainable for the provider? |
| Main value lens | Customer economics | Customer value + provider economics |
| Ongoing AI operating cost | Often becomes part of customer's environment / economics | Often remains provider cost-to-serve |
| Typical scaling question | Should the customer expand the solution? | Can the provider scale the capability sustainably? |
| Common decisions | PROVE / OPTIMIZE / SCALE | PROVE / OPTIMIZE / RESTRUCTURE / SCALE |
| Common economic risk | Project produces activity but weak customer outcomes | Customers like the feature but cost-to-serve or margins are unattractive |

---

# The workload itself may be identical

The distinction is **not**:

```text
SI workload = one AI architecture
SDC workload = another AI architecture
```

The same support agent, copilot, or domain agent could exist in either model.

Example:

```text
SI
Builds a support agent for a retailer
        ↓
Question:
Does the retailer improve support economics?
```

```text
SDC
Offers a support-agent capability as a product
        ↓
Questions:
Does the customer receive value?
AND
Can the SDC operate it sustainably?
```

The architecture may be similar.

The economic perspective is different.

---

# Why this matters for the field kit

The common reasoning model can remain stable:

```text
WORK
→ MEASURE
→ OUTCOME
→ VALUE
→ ACTION
```

But the VALUE question needs the correct perspective.

## SI

Usually emphasize:

```text
customer baseline
customer outcome
customer economic value
customer investment decision
```

## SDC

Usually emphasize:

```text
customer value
cost per Accepted Work
cost-to-serve
pricing / packaging
revenue / retention
provider unit economics
```

---

# Important implication

For SDC scenarios, a capability can have:

```text
High customer value
+
Poor provider economics
```

or:

```text
Healthy provider margin
+
Weak customer value
```

Neither is a strong long-term position.

A sustainable product capability generally needs both:

```text
Customer Value
+
Provider Economics
```

---

# Working principle

> **Partner type changes the economic lens more than it changes the AI architecture.**

For an SI, the dominant question is usually:

> **Did the customer create enough value from the AI investment?**

For an SDC, the dominant question is usually:

> **Did the customer receive enough value, and can the provider deliver that value sustainably?**

This distinction should guide scenario interpretation without creating separate AI Profitability methodologies for SI and SDC workloads.
